# Участники и управление групповым чатом

Работа в боковой беседе: пользователь запретил использование агентов. Поэтому реализация и отдельный повторный проход проверки выполняются самостоятельно; независимого многоагентного одобрения нет. Браузер без отдельного разрешения не используется.

## Принятые решения и область

- Название группового чата открывает Dialog со списком участников, их фото, именами и должностями.
- У входящих сообщений виден аватар отправителя; удалённый сотрудник сохраняет имя и fallback. Используется общий UserAvatar и защищённые адреса фотографий.
- Создатель (администратор группы) и администраторы CRM, состоящие в группе, могут переименовать группу, добавить действующих сотрудников и удалить других участников. Обычные участники видят состав и могут покинуть группу.
- Удаление участника и выход всегда требуют ConfirmDialog. Создатель при выходе выбирает действующего участника, которому передаёт управление; при выходе последнего участника группа остаётся без членов с сохранённой историей.
- Проверки членства и управления выполняются на сервере. Изменения состава транзакционны, сериализуются блокировкой группы. Событие обновления получает прежний и новый состав, включая исключённого сотрудника.
- Не добавляются описание, обучающие подсказки, info-иконки или баннеры. Новые строки RU/EN добавляются в i18n до UI. Ошибки отображаются краткими переведёнными сообщениями, без необработанного текста сервера.
- Схема БД не меняется, миграции не создаются и не запускаются. Поле created_by используется как текущий администратор группы, creator_name меняется вместе с передачей управления.

Файлы: shared/contracts/chat-groups.ts; server/modules/chat/application/ports.ts; server/storage/chat-group*.storage.ts; server/routes/chat-groups.routes.ts; client/src/features/messages/chat-groups-api.ts; client/src/components/ux/chat/GroupChatThread.tsx и новые Dialog в этой папке; client/src/components/ux/ChatSheet.tsx; chatGroup-ключи i18n и удаление устаревшего messageUploadHint; tests/chat-group*, tests/group-chat.dom.test.tsx; docs/chat-group-management-*.md.

Зависимости для чтения: UserAvatar, ConfirmDialog/UnsavedChangesGuard, Dialog/Button/Input/Checkbox/Label, user-photo contract, auth/leadership helpers, websocket invalidation, message attachments и настройки проверок. Прочие сценарии и работа основной беседы не изменяются.

## Приёмка и проверки

1. Список участников открывается нажатием названия, работает с клавиатуры и остаётся модальным.
2. Аватары сообщений и участников имеют безопасный URL, fallback сохраняется.
3. Переименование/добавление/удаление доступны по правам, подмена запросов не обходит проверку.
4. Отмена опасного действия не вызывает API; успешный выход убирает группу и её открытые данные из интерфейса и кэша.
5. Удаление/выход сохраняет историю; создатель не оставляет действующих участников без администратора.
6. Недоступные сотрудники, лимит участников, отсутствующий преемник, удалённый/не входящий участник обрабатываются конкретными ошибками. Запросы и уведомления не раскрывают группу посторонним.
7. Запустить npx tsc --noEmit, адресные DOM/API/storage/message tests, i18n/architecture/responsive/encoding/lint и git diff --check. Полный набор остаётся в CI перед deployment; полный локальный набор не запускается.
8. Сохранить снимок перед следующим раундом исправлений; отдельно прочитать финальный diff и тестовые ожидания. Независимый агент/браузер запрещены условиями боковой беседы.

Отдельные предложения без реализации: отключение уведомлений группы, поиск по сообщениям, закреплённые сообщения.
