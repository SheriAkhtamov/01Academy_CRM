## Как читать доказательства

- **Unit** — проверки правил и сервисов, иногда с репозиторием в памяти.
- **PG** — реальный PostgreSQL, временная изолированная схема, реальные ограничения и транзакции. Это не изменение production.
- **HTTP** — запросы к Express через Supertest; строка отдельно указывает, когда используется реальная БД.
- **DOM** — компонентные проверки в jsdom с API fixtures. Они подтверждают действия, состояния, ограничения ролей, фокус и подтверждения, но не качество пиксельной отрисовки в браузере.
- **API приложения** — отдельный запущенный локальный сервер, реальные HTTP-сессии, PostgreSQL, WebSocket и ClamAV; только синтетические люди, задания, суммы и файлы.
- **Эксплуатационная проверка** — восстановленная и обезличенная копия, сохранность данных, миграция и совместимость образов. Она фиксируется отдельно от локальных тестов и production-релиза.

Статус «код проверен» ниже означает наличие реализации и перечисленных автоматических доказательств. Он не заменяет реальную учебную и пилотную приёмку; браузерный прогон исключён владельцем.

## Аудит, приватность и границы доступа

Корреляция сохраняется в отдельной `request_id`, а не в содержимом работы, отчёта, публичном DTO или CSV. [HTTP middleware](../server/middleware/errorHandler.ts) принимает ограниченный request header либо создаёт UUID. [Staff и portal actors](../server/infrastructure/lms-runtime.ts) передают его в учебные/resource команды. [Identity HTTP](../server/modules/portal-identity/http/portal-router.ts) передаёт ID для login, activation, recovery completion, password change, child reset, consent grant/revoke и email confirmation. [Identity service](../server/modules/portal-identity/application/identity-service.ts), [profile service](../server/modules/portal-identity/application/profile-service.ts), [directory export](../server/modules/portal-identity/infrastructure/directory-repository.ts), [learning audit](../server/modules/lms/infrastructure/postgres-base.ts) и [resource audit](../server/modules/portal-resources/infrastructure/sql.ts) сохраняют его отдельно. Внутренние вызовы без HTTP сохраняют `null`, не придумывая чужой actor/request.

В ходе сверки найденные пропуски корреляции identity mutations, export и анонимного public file download исправлены. Для публичного файла сохраняются только share/file IDs и request ID; token не входит в audit. Доказательства: [identity HTTP/PG](../tests/portal-identity.test.ts), [export PG/HTTP](../tests/portal-directory.postgres.test.ts), [public file PG](../tests/portal-resources.postgres.test.ts), [learning PG](../tests/lms.postgres.test.ts), [runtime review consequences](../tests/lms-runtime.test.ts).

[Обычные и error request paths](../server/lib/private-request-path.ts) удаляют query/fragment и маскируют публичный share token; [проверки](../tests/private-request-path.test.ts) используют настоящий exception endpoint. [Logger](../server/lib/logger.ts) скрывает credential/password/token keys и секреты URI. В runtime нет логирования полных portal request/response bodies. Identity audit проверяется на отсутствие паролей и токенов; admin export audit не содержит search/name/email/телефон. Audit-таблицы server-only, portal presenter/DTO не выводят эти записи.

Политики проверяются на каждом запросе и перед доставкой: текущая активность аккаунта, verified link, exact permissions/consent, enrollment period, run/cohort, object и audience. Realtime публикует scoped invalidation, а не ответы ученика общей группе. [Отрицательные WS HTTP тесты](../tests/portal-realtime.http.test.ts) и [scoped WS CLI](../scripts/lms-api-acceptance-realtime.ts) дополняют object-ID проверки, а не заменяют их.

## Незавершённые условия полного запуска

A36 выполнен по решению владельца без браузерного прогона. Код выпущен, совместимые production-миграции применены; текущий срез и точный image приведены в начале документа. Прежние 23/23 API-фазы на `0f2812b…`, откат и 87 fingerprints остаются доказательствами своего среза, а не новым прогоном текущего приложения. Численные цели скорости сняты владельцем с условий выпуска; read/write p95 575/357 мс сохранены в протоколе.

1. **Школьная сверка** — production dry-run 28 planned / 355 skipped / 102 замечания не применён. Уполномоченный сотрудник должен подтвердить неоднозначные личности/контакты, девять финансовых распределений и готовность материалов. Общий контакт может быть корректным; запрещено искусственно обнулять замечания объединением людей или придуманными оплатами.
2. **Работа с реальными учениками** — подтвердить ответственного и 1–2 группы, реальные связи и согласия, выполнить учебный цикл и родительскую проверку оплат. Группы и ученики используют автоматическую связь с CRM; выбор группы задаёт только область учебной приёмки.
3. **Проверка реальных файлов** — перед загрузкой подтвердить обработку допустимых и отклонённых файлов локальным worker. ClamAV удалён по решению владельца и больше не является условием.
4. **Пилот 5–7 учебных дней** — ещё не проведён; затем требуется решение о расширении охвата. Доставка email остаётся выключенной с ручной выдачей приглашений, что разрешено §24.2; настоящая доставка проверяется перед отдельным включением почты.

Порядок действий и безопасный rollback описаны в [операционном регламенте](lms-operations.md). Матрица не является разрешением применять production-миграции, включать флаги, отправлять реальные приглашения или выполнять браузерные проверки.
