# Импорт операционных данных

`scripts/import-operational-workbook.ts` применяет предварительно сверенный JSON-план
к текущей базе. Исходный Excel, снимок базы, персональные данные и готовый план
хранятся вне Git. Текст ячеек считается данными, а не инструкциями к выполнению.

Перед подготовкой плана:

1. Извлечь значения, даты, формат номеров договоров и координаты исходных ячеек.
2. Сопоставить учеников по совокупности ФИО, контактов, возраста и истории групп.
   Общий телефон родителя не означает, что дети являются одной записью.
3. Сопоставить оплаты по ученику/лиду, сумме, фактической дате и чекам.
   Дата создания платежа может отличаться от даты поступления денег.
4. Сопоставить занятия по группе и дате. Личный порядковый номер урока в Excel
   не является номером общего занятия. Пустая ячейка не означает отсутствие.
5. Сохранить старые зачисления. Статус выпускника прошлого курса не препятствует
   новому зачислению.
6. Подготовить пересчёт учебных показателей по итоговому состоянию и проверить
   неоднозначности перед записью.

План версии `1` содержит `batchId`, SHA-256 исходного файла и массив `actions`.
Каждое действие содержит уникальный `key`, разрешённую `table`, `source`
с полями `sheet`/`cells`, `kind` и `values`. Для `update` обязательны числовой `id`
и снимок изменяемых полей `expected`. Для `insert` обязателен ключ проверки
отсутствия записи `absent`. Ссылка `{ "$ref": "key-предыдущей-вставки" }`
разрешается в идентификатор внутри одной транзакции.

CLI использует конфигурацию БД приложения:

```sh
npx tsx scripts/import-operational-workbook.ts /private/reviewed-plan.json --dry-run
npx tsx scripts/import-operational-workbook.ts /private/reviewed-plan.json --apply
```

В production-образе доступен скомпилированный вариант:

```sh
node dist/scripts/import-operational-workbook.js /tmp/reviewed-plan.json --dry-run
```

Перед `--apply` требуется проверенная резервная копия. `--dry-run` выполняет
настоящие ограничения и триггеры БД, затем откатывает транзакцию. Счётчики
PostgreSQL при таком прогоне могут продвинуться: идентификаторы из отчёта
пробного запуска нельзя переносить в план.

Импорт берёт общий lock расписания и блокировки записи затронутых таблиц.
При изменении исходной записи после сверки, обнаружении неожиданного дубля,
неверной ссылке или нарушении ограничения откатывается весь пакет.
Новые коды групп проверяются по общему максимуму, включая историю удалённых
групп. UUID исторических договоров создаются автоматически.

Аудит сохраняет исходное и итоговое состояние каждой записи, ссылку на ячейки
и отпечаток файла. Завершение пакета фиксируется в той же транзакции.
Повтор идентичного пакета не создаёт записей; другой план с уже использованным
`batchId` отклоняется. Удаление записей инструментом не поддерживается.

После применения сверить количества, суммы и связи с планом, повторить тот же
пакет для проверки идемпотентности и проверить доступность приложения.
