# Удаление оценок обновлений

## Запрос и решение

Пользователь требует полностью убрать функцию оценок «Как вам обновление? / Полезно / Круто / Ждали» из раздела «Что нового».

- Удалить весь контейнер оценок, без пустой панели и дополнительных отступов.
- Удалить state/effect/handler и imports реакций статьи, все функции/типы/константы хранения реакций из utils, соответствующие RU/EN переводы.
- Не добавлять миграции, API, фоновую очистку старого localStorage или новые пользовательские тексты. Прежние локальные значения больше не читаются и не записываются приложением.
- Сохранить статью в Card, возврат/соседние посты/оглавление/прогресс/кнопку наверх, обычное прочтение, поиск/год, Dialog изображения, нового поста и быстрого просмотра, все подтверждения редактора.
- Удаление оценок касается только обновлений; другие реакции/оценки/уведомления системы вне области.

## Область

- client/src/features/updates/UpdateArticle.tsx, utils.ts.
- client/src/lib/i18n.ts — только updatesReactionsTitle и updatesReaction* ключи. Сохранить чужие изменения чатов.
- tests/platform-updates.dom.test.tsx — заменить тест переключения оценок адресной регрессией отсутствия оценок и обращений к старому хранилищу в RU/EN.
- Остальные client/src/features/updates/**, shared/contracts/platform-updates.ts и tests/platform-updates*.test.ts — только чтение/адресная проверка сохранённых сценариев.
- Общие Card/Dialog/Button, useTranslation — только чтение при необходимости.
- AGENTS.md, package.json, tsconfig/Vitest/проверочные scripts, .github/workflows/deploy.yml — чтение правил/проверок, без изменений.
- docs/updates-reactions-removal-*.md — область, задания, отчёт и договорённости.

Не исследовать и не изменять модули сообщений, чатов или других экранов. В checkout параллельно работают над чатами и i18n; общие Git index и чужие изменения не трогать.

## Владельцы и цикл

- Координатор: снимки, письменные решения, итоговый diff и содержание тестов, самостоятельный npx tsc --noEmit после раунда, static checks/адресные tests, main commit/push, полный CI и deployment.
- updates_critic: независимый строгий критик, только docs/updates-reactions-removal-review.md. Постепенно фиксирует ID/важность/место/дефект/критерий; код не меняет. Повторная проверка до явного одобрения.
- updates_frontend: UpdateArticle.tsx и tests/platform-updates.dom.test.tsx.
- updates_backend: utils.ts и только согласованные ключи i18n.
- Исполнители напрямую обсуждают границу удаления, сохранение чтения/черновиков/навигации, проверяют diff друг друга и сообщают замечания владельцу. Изменения общего словаря согласуются по ключам.
- Перед исправлениями дождаться письменного задания координатора по первому отчёту критика.

## Приёмка

1. Нет активного UI оценок, типов, утилит, storage key или перевода функции в приложении. Упоминание retired key допустимо в тесте, который проверяет отсутствие обращений.
2. Статья сохраняет поверхность Card и обычные сценарии; после текста идут соседние посты/кнопка наверх, без пустого контейнера оценок.
3. DOM-тесты проверяют RU/EN, ранее сохранённые оценки не порождают UI и не читаются/записываются при открытии и смене статьи. Сохраняются проверки навигации, чтения, модальных окон и редактора.
4. Новых подсказок и текстов UI нет, неиспользуемые ключи оценок удалены.
5. Исполнители завершили взаимную проверку; координатор сам проверил код/tests и запустил tsc/static checks/адресные tests; критик повторно явно одобрил результат.
6. Полный набор только в GitHub Actions перед deployment; браузер и скриншоты не запускать без отдельного разрешения пользователя. DOM/jsdom допустимы.
7. Изменения этой задачи отправлены в main без дополнительной ветки, чужие незавершённые правки сохранены.

Координатор сохраняет весь исходный working/staged diff и затронутые файлы в /tmp/academy-updates-reactions-baseline до реализации.
