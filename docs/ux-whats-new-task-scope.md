# UX/UI Спецификация: Обновление страницы «Что нового» (Updates / Changelog)

## 1. Область задачи (Scope)
Затронутые файлы и модули:
- `client/src/features/updates/UpdatesPage.tsx` — Лента обновлений (Cards Grid), детальный просмотр статьи (Article View), оглавление, навигация, поиск и фильтры.
- `client/src/features/updates/PublishUpdateDialog.tsx` — Модальное окно публикации (Dialog) с живым предпросмотром, индикаторами валидации по языкам и выбором действия CRM.
- `client/src/lib/i18n.ts` — Словари переводов (RU/EN) для всех новых пользовательских текстов.
- `tests/platform-updates.dom.test.tsx` — Интеграционные DOM-тесты для сценариев чтения, копирования ссылки, фильтрации, модального зума и публикации.

## 2. Пользовательские сценарии и требования

### Сценарий 1: Обзор ленты релизов (Cards Grid)
1. Пользователь открывает раздел «Что нового».
2. Вверху отображается статистика релизов (общее количество, дата самого свежего обновления).
3. Поле быстрого поиска по тексту (заголовок, аннотация, тело) с мгновенной фильтрацией.
4. Фильтр-чипсы по годам/периодам (например: «Все», текущий год и т.д.).
5. Обновления выводятся адаптивной сеткой информативных карточек (Cards Grid):
   - Дата релиза и значок «Новое» для самого последнего обновления.
   - Расчётное время чтения (например, «2 мин чтения»).
   - Превью первого скриншота поста (если есть).
   - Заголовок и выжимка.
   - Кнопка «Читать обновление».
   - Кнопка «Копировать ссылку» с toast-уведомлением.
   - Кнопка быстрого перехода в затронутый модуль CRM (при наличии права доступа).
6. При отсутствии результатов поиска отображается аккуратное пустое состояние с кнопкой сброса поискового запроса.

### Сценарий 2: Детальное чтение статьи (Article View)
1. Пользователь переходит к конкретному обновлению (`/updates?post=ID`).
2. Вверху страницы: кнопка «Все обновления», кнопка «Копировать ссылку» и индикатор прогресса чтения.
3. Если статья содержит 3 и более разделов, выводится интерактивное оглавление (Table of Contents) с якорными ссылками для быстрого перехода к разделам.
4. Скриншоты кликабельны и открываются в полноэкранном модальном окне `Dialog` (строго соблюдая модальный паттерн).
5. Внизу статьи отображаются навигационные блоки перехода: «Предыдущее обновление» и «Следующее обновление».
6. Кнопка «Наверх» для быстрого возврата к началу лога.

### Сценарий 3: Создание и публикация обновления (Publish Dialog)
1. Руководитель нажимает «Новый пост».
2. Открывается модальное окно `Dialog` (сохранение модального паттерна обязательно).
3. Вкладки RU / EN с визуальной индикацией готовности (галочка/статус заполнения).
4. Режим живого предпросмотра (Preview): автор может переключить вкладку предпросмотра и увидеть, как статья будет выглядеть для читателей.
5. Селектор целевого действия CRM (например, переход в «Группы» в продажах или «Структуру академии»).
6. Счетчики символов для заголовка и аннотации.
7. Сохранение защиты от случайной потери данных (`useUnsavedChangesGuard`).

## 3. Ограничения и правила проекта (AGENTS.md)
1. **Сохранение модальных окон**: `Dialog` для публикации и зума изображений строго остаются модальными окнами.
2. **Запрет хардкода текста**: все строки добавляются в `client/src/lib/i18n.ts` и проверяются скриптом `npm run check:i18n`.
3. **Запрет технических подсказок**: никаких подсказок об устройстве API, базы данных или внутренних ограничениях.
4. **Тестирование**: `npm test -- tests/platform-updates.dom.test.tsx` и `npx tsc --noEmit` обязаны проходить без ошибок.

## 4. Критерии приёмки (Acceptance Criteria)
- [ ] Лента релизов отображается в виде красивой адаптивной сетки карточек (Cards Grid) с датой, расчетом времени чтения, бейджем свежего обновления и превью скриншота.
- [ ] Поиск в реальном времени фильтрует карточки по названию, выжимке и содержимому; есть чипсы годов и кнопка сброса.
- [ ] В детальном просмотре есть оглавление для длинных постов, копирование ссылки со всплывающим уведомлением, индикатор чтения и навигация между соседними постами.
- [ ] В модальном окне публикации есть вкладка «Предпросмотр», индикаторы заполнения языков, счетчики символов и выбор действия CRM.
- [ ] Все тексты локализованы на RU и EN, отсутствуют технические подсказки.
- [ ] Все тесты проходят успешно, TypeScript компилируется без ошибок.
