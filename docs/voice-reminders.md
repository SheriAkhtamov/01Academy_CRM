# Голосовые напоминания о демо

## Статус на 13 октября 2026 года

Реализованы настройки и загрузка записи в модальном окне OnlinePBX, очередь
напоминаний, два параллельных исполнителя, общий резерв каналов с менеджерами,
отмена при переносе демо или изменении участника и журнал результатов.
По умолчанию напоминания выключены. Попытка включения при неизвестной общей
занятости АТС отклоняется. В production источник общей занятости пока не
подключён; `createPbxCapacityProvider` без него возвращает `known: false`.

Робот использует существующих пользователей 100 и 101 с отдельными Verto
сессиями. Новые рабочие места и автоинформатор не подключаются. Учёт каналов
ограничивает суммарную работу менеджеров и роботов двумя внешними звонками.
Освободившийся исполнитель сразу берёт следующее задание, пока второй звонок
продолжается. Неизвестная занятость закрывает допуск роботу.

Успешный тест на разрешённом пользователем номере подтвердил воспроизведение
аудио через OnlinePBX. Пользователь подтвердил слышимость сигнала. Исправлена
совместимость с SDP OnlinePBX без `a=mid`; воспроизведение начинается только
после ответа и установки ICE/DTLS. Статус «Воспроизведено» означает передачу
полной записи, а не доказательство того, что человек её прослушал.

## Почему нельзя включить очередь сейчас

Официальная [документация API](https://onlinepbx.evateam.ru/docs/docs/DOC-000051#api)
направляет на [WebSockets API 3.0](https://pbx38153.onpbx.ru:3342/documentation/index.html).
Адрес подключения — `wss://<домен>:3342/?key=<API-ключ>`; используется уже
имеющийся ключ HTTP API. Ключи остаются на сервере и не передаются в CRM UI.

Подписка `calls` получает события создания и завершения каналов. Однако её
ответ `subscribed` содержит только перечень групп событий. Полный снимок
активных звонков, отметка окончания начальной синхронизации и возобновление
событий с checkpoint в опубликованной схеме отсутствуют. Живая проверка
подтвердила, что подключение во время уже идущего тестового звонка не получает
его события `channel_create`; последующие события ответа и завершения приходят.
После старта или переподключения нельзя считать пустой локальный список
доказательством свободных каналов.

HTTP-история содержит завершённые звонки, а SIP dialog/BLF для 100/101 не
показал активный Verto-звонок. Поле `gateway_id` у событий также нельзя просто
считать количеством внешних каналов: оно встречается на внутренних плечах.
Переадресация может занимать несколько внешних плеч одного звонка.

Нужен подтверждённый провайдером источник текущего количества занятых внешних
каналов и занятости пользователей, включая входящий маршрут до подключения
менеджера, WebRTC, SIP, удержание, перевод и внешнюю переадресацию.

## Подготовленный запрос в поддержку OnlinePBX

Сообщение подготовлено для согласования; не отправлено.

> Для аккаунта pbx38153.onpbx.ru создаём в своей CRM голосовые напоминания через
> существующих WebRTC-пользователей 100 и 101. Лимит аккаунта — два одновременных
> внешних звонка. Нужен достоверный снимок текущей занятости внешних каналов и
> пользователей перед исходящим вызовом, включая входящие звонки на маршруте,
> удержание и внешнюю переадресацию.
>
> WebSockets API 3.0 на порту 3342 работает. Подписка calls получает новые
> channel_create/channel_destroy, но при подключении во время уже идущего
> звонка его channel_create не приходит. Есть ли документированный метод
> полного снимка активных внешних каналов или способ начальной синхронизации
> с явной отметкой завершения? Как восстановить состояние после разрыва связи
> и корректно считать несколько внешних плеч переадресованного звонка?
>
> Мы не используем автоинформатор OnlinePBX и не запрашиваем дополнительные
> рабочие места. Просим уточнить доступность и стоимость такого API в нашем
> текущем тарифе.

## Условия активации

1. Подключить подтверждённый источник общей занятости в composition root.
   При потере связи или незавершённой синхронизации возвращать `known: false`.
2. Проверить старт при уже занятых двух каналах, один свободный канал, входящий
   звонок на маршруте, две параллельные линии и восстановление после reconnect.
3. Загрузить запись пользователя и выбрать время напоминания и разрешённые
   часы в CRM. Аудио хранится в приватном каталоге uploads/voice-reminders.
4. Выполнить проверку на согласованных тестовых номерах и затем включить
   напоминания. Поддержка готовности и настройки доступны только руководителям.

Миграция `0142_voice_reminders.sql` запускается обычным CI/deploy процессом до
старта сервера. Очередь использует PostgreSQL leases, отменяет устаревшие
задания и не повторяет неоднозначные попытки после падения процесса. Callback
робота перехватывается до создания контакта и атрибуции менеджеру; неоднозначные
callback сохраняются отдельно и не увеличивают KPI менеджеров.

Локально запускать только тесты voice-reminders, voice-verto, voice-provider,
voice-telephony-webhook, telephony-channel-reservations и затронутые сценарии
менеджерского телефона. Полный набор выполняется в GitHub Actions.
